### [E10] Fixture de teste monta índice `refs_por_chave` sobre heap sem campo de organização
- Arquivo: tests/test_selection.py:113  | Categoria: outro (defeito no teste)
- Como foi detectado: teste `test_combinacao_invalida_ValueError_sem_io[...-A6]` (KeyError: None)
- Código bruto (tag raw-E10): `ix.insert(r[c], r[tabela.campo] if por_chave else rid)`
- Correção: no heap `tabela.campo` é None; a ref passa a ser a chave primária do esquema
  (`tabela.campo or ALUNO.chave[0]`). Assim o caso monta o índice e testa o que deveria: `select`
  rejeitar (ValueError) índice `refs_por_chave` sobre organização que não é B+.

### [E10] Asserção vazia no custo por ref do índice secundário (teste sempre passava)
- Arquivo: tests/test_selection.py (`test_indice_secundario_rid`)  | Categoria: outro (defeito no teste)
- Como foi detectado: revisão do código gerado, **antes** do commit `ia-raw(E10)` — por isso o trecho
  abaixo **não** está na tag `raw-E10` (lá já consta a versão corrigida).
- Código bruto (pré-tag): `assert met["por_area"]["dados"]["requests"] == len(res) if "por_area" in met else True`
  — `Metricas` só tem as chaves de `CHAVES_STATS` (sem `por_area`), então a expressão virava `assert True`
  e o teste nunca verificava que cada ref custa 1 acesso ao arquivo de dados (15.2, A4/A6).
- Correção: como `_conferir` zera as stats antes da operação, a asserção passou a ler o contador real da área:
  `assert ctx.buffer_stats()["por_area"]["dados"]["requests"] == len(res)`.

### [E11] Merge com buffers de entrada pinados causava thrash da página de saída
- Arquivo: src/executor/sort.py (`_merge`)  | Categoria: memória da junção / eficiência
- Como foi detectado: teste `test_transferencias_proximas_do_livro` (área 'trabalho' = M, buffer frio):
  1449 transferências medidas vs 816 do livro (M=3, b=68).
- Código bruto (tag raw-E11): `paginas = len(grupo) * bb; mb.reservar_paginas(paginas); mb.reservar_paginas_io(bb)`
  — com a área = M sobrava 1 frame livre para ler os runs **e** para o append da saída; cada recarga de
  cursor expulsava a página de saída (dirty → gravação) e o append seguinte a relia.
- Correção: os N·bb buffers de entrada passam a ser contados como páginas de E/S (`reservar_paginas_io`),
  pois são os próprios frames em que `records_in_block` lê os blocos. Medido agora: 800 vs 816 (M=3), 422 vs 408 (M=5).

### [E11] Teste exigia que toss-immediate sozinho reduzisse leituras da interna do BNL
- Arquivo: tests/test_join_nl.py (`test_bnl_mru_e_toss_reduzem_leituras_da_interna`)  | Categoria: outro (defeito no teste)
- Como foi detectado: suíte com `--so-fakes` (FakeBufferManager): 120 < 120 falhou.
- Código bruto (tag raw-E11): `assert leituras[("LRU", True)] < leituras[("LRU", False)]`
- Correção: `<=`. Toss-immediate (13.5.1) só antecipa a expulsão da página; quem reaproveita a interna
  entre varreduras é a MRU (15.5.2) — essa asserção estrita continua no teste.
